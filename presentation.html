CI/CD in one sentence

Robots check every change (CI) and robots deliver it (CD) — broken stuff never reaches friends.

CI = Continuous Integration = robot inspectors 🔍

An assembly line for code.

Walk left to right. Each box is one 'job' in our GitHub Actions file. Nothing skips ahead — the line moves one box at a time.

Stage 1 · Lint 🔍 — the spell check

A robot reads your code like a teacher spell-checking an essay. Typos, missing brackets, messy lines — flagged.

In the lab: job "lint" runs npm run lint — it parses every JS file and checks the HTML wiring. If it fails, the line stops right there.
Lint is cheap and fast, so it runs first, in parallel with tests. Nobody ships with spelling mistakes — why ship with code mistakes?

Stage 2 · Test 🍪 — the taste test

Robot tasters follow a checklist: Does the counter start at 0? Does it count up? What if someone asks for a half-cookie (a non-integer)? It must say NO.

In the lab: job "test" runs npm test — 5 tiny robot taste-testers.
A test is a checklist item. Failing means the recipe is wrong — not that the robot is mean. The robot is doing its job.

Stage 3 · Build 📦 — pack the box

Gather the page (HTML + CSS + JS) into one neat box called dist/. Stick on a label: version, date, commit.

In the lab: job "build" runs npm run build, then hands the box to GitHub (the "artifact").
Same ingredients → same box, every time. The box is called an artifact. Deploy never touches your source folder — only the box.

Stage 4 · Deploy 🚚 — the delivery truck

The truck carries the box to the giant library called GitHub Pages, where anyone with the link can read it.

In the lab: job "deploy" — and the truck ONLY leaves for pushes to main. Homework proposals (PRs) never get a truck.
Preview the gate concept: propose ≠ publish. Ask the kids when a truck should leave — only after the robots say yes.

When it breaks 🔴 — the GOOD news

You forgot the sugar. The taste test fails ❌. The pipeline STOPS. The truck never leaves. You fix the recipe, the robots check again, everything goes green.

Red is good: the robots caught it BEFORE your friends saw it.

This is the emotional core of the whole talk. Failure here is protection, not shame. Draw the loop: break → red → fix → rerun → green.

Presenter script: click Actions in the repo, open the newest green run — four jobs, four checkmarks, top to bottom. Then open any non-main run: three green and one grey "skipped". Ask the kids: "did the truck leave?" No — because it was not main. Same code, same robots, different door. The BUILD_INFO.json trick is worth pointing out: the live site can tell you which commit it came from, so "it works on my machine" becomes checkable.
